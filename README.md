# NVLearn

NVLearn is a Flask-based study companion that helps students turn their notes into active learning material. It combines note taking, AI-assisted organization, flashcards, quizzes, search, and email verification in one personal study workspace.

## What This Project Solves

Students often collect notes but do not always have an easy way to revise them actively. NVLearn solves that by turning a simple note library into a study system:

- Store personal notes in one account-based workspace.
- Automatically generate metadata such as tags and summaries for notes.
- Search through notes from the navigation search using keyword matching combined with vector similarity.
- Use AI note actions with vector similarity search across note titles, tags, summaries, and note content.
- Filter notes by tags extracted as part of note metadata generation.
- Sort the notes list by title or recent activity.
- Ask an AI assistant to create notes, retrieve relevant notes, modify notes, generate flashcards, and generate quizzes.
- Save useful flashcard sets and quiz results for later practice.
- Keep unfinished AI-generated flashcards and quizzes temporary so the database does not fill up with unused practice material.

In short: NVLearn helps a learner move from passive note storage to active revision.

## Architecture at a Glance

NVLearn uses the Flask **application factory** and **blueprint** patterns. Each user-facing feature is a self-contained blueprint under `app/<feature>/`, and shared business logic lives in `app/services/`. This keeps route handlers thin and lets the same helper serve both a route and a background job.

```text
run.py                          ← start here (dev)
    │
    ▼
app/__init__.py  (create_app)
    ├── loads Config (app/config.py)
    ├── initializes db, migrate, login_manager (app/extensions.py)
    ├── registers blueprints
    │     ├── main/      auth/      notes/      uploads/
    │     └── diagrams/  ai/        practice/
    ├── runs db.create_all()
    └── starts APScheduler (app/jobs.py)
                │
                ▼
        app/services/*          ← shared business logic
                │
                ▼
        helpers.py, vector_store.py, prompts.py
        (external integrations + utilities)
```

**Why this pattern?**

- **Testability** — `create_app(TestConfig)` returns an isolated app per test run, so tests don't share state or a running server.
- **Isolation** — changes to one blueprint can't accidentally affect another; each imports only what it needs.
- **Discoverability** — "the AI code is in `app/ai/`" is easier to find than grepping a single 2000-line file.
- **No URL changes** — blueprints were added without URL prefixes, so every existing HTTP route, bookmark, and JavaScript `fetch()` call still works exactly as before.

```powershell

```

Then activate again:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 4. Install Dependencies

Install the project dependencies from `requirements.txt`:

```powershell
pip install -r requirements.txt
```

Optional but recommended:

```powershell
python -m pip install --upgrade pip
```

### 5. Create the Environment File

Copy `.env.example` to `.env`:

```powershell
copy .env.example .env
```

Then edit `.env` and replace the placeholder values.

### 6. Install with a Provided Database

If you received a pre-made `notes.db` file, use it to start with its existing accounts, notes, diagrams, flashcards, and quizzes. Database files are intentionally excluded from Git, so obtain the file through the project owner or another approved private channel; it is not part of a normal clone.

Before copying it, stop NVLearn if it is running and preserve any database you already have. From the project folder in PowerShell:

```powershell
New-Item -ItemType Directory -Force instance
Copy-Item "C:\path\to\provided\notes.db" ".\instance\notes.db"
```

Do not overwrite an existing `instance/notes.db` unless you intend to replace all local application data. Make a backup first:

```powershell
Copy-Item ".\instance\notes.db" ".\instance\notes.backup.db"
```

The SQLite database does not include the local ChromaDB vector index. After copying the database and configuring `.env`, rebuild the index:

```powershell
python sync.py
```

The script indexes every active (non-binned) note and reports the sync result. It may take time for large note libraries and uses the configured embedding service, so run it only when the index is missing or stale — for example after copying `notes.db`, deleting `instance/chroma_db/`, or changing the embedding model. If notes fail to sync, check the terminal logs and run the command again after resolving the reported issue.

### `CLOUDFLARE_API_TOKEN`

This token authenticates NVLearn's AI intent router with Cloudflare Workers AI. The router uses the Workers AI REST API and the `@cf/meta/llama-3.1-8b-instruct` model to decide whether a request should be handled as chat, note creation, note retrieval, note editing, flashcard generation, or quiz generation. Gemini then generates the requested study content.

To create the token:

1. Sign in to the [Cloudflare dashboard](https://dash.cloudflare.com/).
2. Open **AI** → **Workers AI**, then choose **Use REST API**.
3. Select **Create a Workers AI API Token**, review the prefilled scope, create the token, and copy it immediately.
4. Paste it into `.env` as `CLOUDFLARE_API_TOKEN`.

If you create a custom token instead of using Cloudflare's Workers AI token flow, scope it to the account used by NVLearn and grant both **Workers AI - Read** and **Workers AI - Edit**. Do not use a broad Global API Key or add unrelated permissions. Store the token only in `.env`; it cannot be recovered from Cloudflare after leaving the creation screen. Cloudflare's current REST API guidance documents these permissions and the dashboard flow. [Cloudflare Workers AI REST API guide](https://developers.cloudflare.com/workers-ai/get-started/rest-api/)

Example:

```env
CLOUDFLARE_API_TOKEN=your_cloudflare_api_token
```

### `CLOUDFLARE_ACCOUNT_ID`

This is the Cloudflare account identifier used to build the Workers AI API URL. From **AI** → **Workers AI** → **Use REST API**, copy the displayed **Account ID** and add it to `.env`.

Example:

```env
CLOUDFLARE_ACCOUNT_ID=your_cloudflare_account_id
```

Used by `ask_gemini()` for content generation tasks, including:

The app attempts several Gemini model names in sequence. If one fails, it tries the next one.


That creates the database tables if they do not exist.

### Managing Schema Changes with Flask-Migrate

This repository already includes Flask-Migrate, an Alembic migration environment in `migrations/`, and existing migration revisions. Use migrations whenever a model changes so existing local or deployed databases can be upgraded without being recreated.

Run all commands from the project folder with the virtual environment activated. Set `FLASK_APP` once per terminal session so you can omit `--app` from every command:

```powershell
$env:FLASK_APP = "app:create_app"
```

For an existing database created before the diagram-restoration columns were added, first back up `instance/notes.db`, then run:

```powershell
flask db current
flask db upgrade
```

`db current` shows the revision applied to the configured database. `db upgrade` applies every pending revision. Run it after pulling changes that add a migration and before starting the app in an environment that already has a database.

If you prefer not to set `FLASK_APP`, prefix each command with `--app` instead:

```powershell
flask --app app:create_app db current
flask --app app:create_app db upgrade
```

For a brand-new local database, the application startup hook creates the current tables with `db.create_all()`. Because the included migration history begins with an alteration to an existing `diagrams` table rather than a full initial-schema migration, mark that already-current fresh database as up to date instead of running `db upgrade`:

```powershell
flask db stamp head
```

Use `db stamp head` only after confirming that the database was created from the current models and already has the expected schema. It records the revision without executing migrations.

The same rule applies to a provided database that was created from this current project version and already contains the `diagrams.original_diagram_data` and `diagrams.dirty_since` columns: use `db stamp head` if it has not yet been stamped. If the database is from an earlier project version, use `db upgrade` after backing it up instead.

After changing a SQLAlchemy model in `app/models.py`, generate a revision and inspect it before applying it:

```powershell
flask db migrate -m "describe the schema change"
flask db upgrade
```

The generated file is placed in `migrations/versions/`. Check the generated `upgrade()` and `downgrade()` operations, commit that file with the model change, and do not edit an already-applied migration in a shared environment. To move back one revision during local development:

```powershell
flask db downgrade
```

`db.create_all()` remains useful for bootstrapping an empty local database, but it does not alter existing tables. Migrations are the mechanism for evolving an existing schema. Back up `instance/notes.db` before applying schema changes to important data.

## OCR and Imported Diagrams

PDF and DOCX uploads are imported as notes. For PDFs, NVLearn first reads the page text directly. If a page is image-only or its text layer is empty, it renders that page at 150 DPI and passes the resulting image to Tesseract OCR. This means OCR quality depends on the source scan; clear, upright pages with readable text work best.

For both PDFs and DOCX files, embedded images are retained as separate diagram records rather than discarded. They are converted to PNG when needed and inserted into the imported note as `![Diagram](/diagram_image/<id>.png)`. Once imported, the images behave like other note diagrams: they can be reopened in Draw.io, edited, and used as visual context for AI note actions.

## Diagram Restoration

When an existing saved diagram is edited, NVLearn keeps its original `xmlpng` data as a rollback snapshot before saving the new version. The editor can restore those diagram IDs through the authenticated `/restore_diagrams` endpoint. This restores the original image and clears the pending-change marker.

As a safety net, a background job checks dirty diagrams every 30 minutes. If a diagram has remained pending for more than one hour, the app automatically restores its original version. Saving the parent note associates the current diagrams with the note and clears their rollback snapshots, making the edits permanent. Draft diagrams that were created in the editor but removed before the note is saved are cleaned up instead of being left orphaned.

## How to Use NVLearn

### 1. Register

Go to `/register`, create an account, and enter the verification code sent to your email.

### 2. Log In

Go to `/login`, enter your credentials, and complete email verification.

### 3. Create Notes

Use `/add_note` to create notes manually. Notes support markdown-style content, and the app stores both markdown and rendered HTML.

### 4. Create and Edit Diagrams

In the note editor, click the **Add Diagram** button in the Quill toolbar to open the Draw.io editor modal. Create or design flowcharts, UML diagrams, or mind maps, and click **Save** inside Draw.io to insert the diagram directly into your note. You can click any existing diagram image inside your note at any time to re-open it in Draw.io and continue editing.

### 5. Import a PDF or DOCX

Use the file-upload option when creating a note and select a PDF or DOCX file. NVLearn extracts document text, falls back to OCR for scanned PDF pages, and preserves embedded images as editable diagrams in the resulting note. Review the imported text — especially text recovered from scans — before relying on it for study material.

### 6. Search Notes

Use the search bar in the navbar to find notes with keyword matching combined with vector similarity search. The search modal calls `/search/<query>` for quick JSON results, and pressing Enter opens `/search-results/<query>`.

AI note actions use semantic vector search instead of title-only matching. When you ask the assistant to summarize, explain, rewrite, edit, or extract information from existing notes, NVLearn searches your ChromaDB note vectors using the note title, tags, summary, and markdown content. For supported actions across the full notebook, the AI can use the special `all_notes` topic to process every active non-binned note instead of matching one topic.

### 7. Filter Notes by Tags

When note metadata is generated, the AI extracts tags and stores them with the note. On `/notes`, select one or more extracted tags to filter the visible notes in the browser. The tag menu prioritizes frequently used and default subject tags, with additional tags available through `More tags`.

### 8. Sort Notes

On `/notes`, use the `Sort By` menu to reorder notes in the browser without changing the database:

- `Title: A to Z`
- `Title: Z to A`
- `Recently Opened`
- `Least recently opened`

### 9. Use the AI Chat

Open `/ai-chat` and ask the assistant to help with study tasks. Example prompts:

```text
Create a note about photosynthesis.
Generate flashcards from my biology notes.
Make a quiz from my latest chemistry note.
Find my notes about recursion.
Summarize my note about databases.
Edit my note about photosynthesis to make it simpler.
Summarize all my notes.
```

### 10. Practice and Analytics

Generated flashcards and quizzes open in their own views. Save the ones you want to keep.

Saved practice material appears in:

```text
/practice-hub
```

Note: only saved quizzes and saved flashcard sets appear in Practice Hub.

Flashcard sessions track which cards are marked **Needs Review**. Saving the set stores its review ratio, and the home page prioritizes up to five saved sets with the highest ratios.

Quizzes work differently from flashcards: completing a quiz shows a score summary, and **Save Quiz** both keeps the quiz and records that completed attempt. Retaking a saved quiz and saving again adds another attempt to its history. The Practice Hub displays quiz analytics when attempts are available, including all-time and most-recent-five averages for correct, incorrect, and unanswered questions. It also breaks these metrics down by relevant quiz tags so you can compare performance across subjects.

## Background Jobs

The app starts an APScheduler background scheduler inside `create_app()` (implemented in `app/jobs.py`) when `run.py` starts the app.

It has four interval jobs:

- Every 10 minutes, generate metadata for notes whose metadata is missing or invalid.
- Every 10 minutes, delete one oldest unsaved flashcard set.
- Every 3 hours, delete all unsaved quizzes that are more than 5 hours old.
- Every 30 minutes, restore diagram edits that have been pending for more than one hour.

Generated flashcards are temporary until saved and may be removed by the next flashcard cleanup run. Generated quizzes are temporary until saved and are eligible for removal after five hours. Saved flashcards and quizzes are not removed by these cleanup jobs.

## Vector Search

NVLearn uses ChromaDB for local semantic note search in AI note-action workflows, including AI edit-note actions.

Vector data is stored locally at:

```text
instance/chroma_db/
```

Each user gets a separate Chroma collection named like:

```text
user_<user_id>_notes
```

When a note is created, edited, or restored, the app upserts the note into ChromaDB. When a note is moved to the bin or permanently deleted, the app removes that note from ChromaDB. To rebuild the vector store from SQLite — for example after copying a database to another machine — run `python sync.py`.

The vector document includes:

- note title
- metadata tags
- metadata summary
- markdown note content

By default, vector results are filtered with a cosine-distance threshold in `vector_store.py`. Requests routed with the `all_notes` topic bypass vector matching and load every active note for supported whole-notebook actions.

## Troubleshooting

### App starts, but registration or login emails fail

Check:

- `EMAIL` is set correctly.
- `APP_PASSWORD` is set correctly.
- Gmail App Passwords are enabled.
- The SMTP server and port in `helpers.py` match your email provider.
- Your email provider has not blocked SMTP sign-in.

### AI chat responds with errors

Check:

- `CLOUDFLARE_API_TOKEN` is present, valid, and has **Workers AI - Read** and **Workers AI - Edit** permissions for the intended account.
- `CLOUDFLARE_ACCOUNT_ID` matches the account that owns the Workers AI token.
- `GEMINI_API_KEY` is present and valid.
- Your Cloudflare Workers AI and Gemini accounts have available quota or billing access.
- The Workers AI model and Gemini model names in `helpers.py` are available for your accounts.

If Cloudflare returns an authentication or authorization error, create a new scoped Workers AI token, confirm the two Workers AI permissions, update `.env`, and restart the Flask app. If the response is a rate-limit error, wait a few minutes before retrying.

### Practice Hub does not show a quiz

Only saved quizzes appear in Practice Hub. After taking a quiz, click `Save Quiz` on the quiz summary screen; this also records the attempt used by the analytics page. Unsaved quizzes can be cleaned up after five hours.

### Database looks empty

The SQLite database is local to the Flask app instance path. Check:

```text
instance/notes.db
```

If you delete this file, the app will create a fresh database on next startup.

### I copied a database, but semantic search cannot find notes

`notes.db` stores the notes, while `instance/chroma_db/` stores the local vector index separately. With `.env` configured, rebuild the index from the copied database:

```powershell
python sync.py
```

Only active notes are indexed; notes in the bin are intentionally excluded. The command may use embedding-service quota and should be run only when the index needs rebuilding.

### A database migration fails or a column is missing

Check the current revision and apply pending migrations:

```powershell
$env:FLASK_APP = "app:create_app"
flask db current
flask db upgrade
```

Or without `FLASK_APP`:

```powershell
flask --app app:create_app db current
flask --app app:create_app db upgrade
```

For an important local SQLite database, first copy `instance/notes.db` somewhere safe. If a generated migration is wrong, correct the migration before it is applied; do not delete or rewrite a migration that has already been used by another environment.

### OCR output is incomplete or inaccurate

Tesseract OCR is used only for PDF pages without extractable text. Use a higher-quality, correctly oriented scan with clear contrast, then review the imported note. PDFs that already contain selectable text bypass the OCR fallback.

### Vector search does not find expected notes

Check:

- `chromadb` is installed from `requirements.txt`.
- The app has write access to `instance/chroma_db/`.
- Notes have been created, edited, restored, or synced on startup.
- The distance threshold in `vector_store.py` is not too strict for your note content.
- The note is not in the bin, because binned notes are removed from vector search.

### CSS or JavaScript changes do not appear

The app sets:

```python
# app/config.py
SEND_FILE_MAX_AGE_DEFAULT = 0
```

That helps reduce caching, but the browser may still cache files. Try a hard refresh.

### Adding a new feature (blueprint)

1. Create `app/myfeature/__init__.py`:

   ```python
   from flask import Blueprint
   bp = Blueprint("myfeature", __name__)
   from . import routes  # noqa: E402, F401
   ```

2. Create `app/myfeature/routes.py`:

   ```python
   from . import bp
   @bp.route("/myfeature")
   def index():
       ...
   ```

3. Register in `app/__init__.py` inside `create_app()`:

   ```python
   from .myfeature import bp as myfeature_bp
   app.register_blueprint(myfeature_bp)
   ```

4. Reference endpoints in templates as `url_for('myfeature.index')`.

### Writing tests

Use the factory with a test config:

```python
# tests/conftest.py
import pytest
from app import create_app
from app.config import Config
from app.extensions import db

class TestConfig(Config):
    TESTING = True
    SQLALCHEMY_DATABASE_URI = "sqlite:///:memory:"
    WTF_CSRF_ENABLED = False

@pytest.fixture
def app():
    app = create_app(TestConfig)
    with app.app_context():
        db.create_all()
        yield app
        db.drop_all()

@pytest.fixture
def client(app):
    return app.test_client()
```

Because `create_app()` accepts a config class, tests never touch `instance/notes.db` or start the real scheduler endpoints.

## Production Notes

This project is currently structured for local development. The application factory pattern (introduced in the blueprint refactor) makes deployment straightforward. Before deploying publicly, consider:

- **WSGI server** — run Gunicorn against the factory: `gunicorn "app:create_app()"`. Do not use `run.py` in production.
- **Secret key** — `Config.SECRET_KEY` already reads from `os.environ.get("SECRET_KEY")`; set that variable in your deploy environment so keys survive restarts.
- **Disable debug** — `run.py` enables debug; a WSGI server bypasses `run.py` automatically. Ensure `FLASK_DEBUG` is not set in production.
- **Production database** — override `SQLALCHEMY_DATABASE_URI` in a `ProdConfig` subclass and point it at PostgreSQL.
- **CSRF for JSON endpoints** — Flask-WTF covers form submissions; JSON POST routes (`/ai-response`, `/save_diagram`, etc.) need a token check
